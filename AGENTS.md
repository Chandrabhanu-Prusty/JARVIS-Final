# Jarvis Development Rules

- Build a lightweight Windows desktop assistant.
- Use React + Vite for the UI.
- Package the UI using Tauri, not Electron.
- Use Python + FastAPI for AI, speech and action services.
- Treat everything under references/ as read-only.
- Never modify reference projects.
- Reuse selected code only after inspecting and simplifying it.
- Rename the final product and visible references to Jarvis.
- Do not blindly replace every occurrence of TARS; inspect technical names first.
- Implement and verify one checkpoint at a time.
- Do not start the next checkpoint without approval.
- Prefer CSS, SVG and Web Audio animations over Three.js.
- Keep CPU, RAM and installation requirements low.
- Avoid databases and vector stores.
- Keep only six recent conversation turns in memory.
- Never hard-code credentials.
- Use backend/.env and commit only .env.example.
- Never execute model-generated terminal commands.
- Local actions must use a strict allowlist.
- Require confirmation before opening an application or external resource.
- Text input must continue working if voice functionality fails.
- Support an on-screen push-to-talk button.
- Support configurable Windows Ctrl+Space push-to-talk.
- Prevent the shortcut from interfering with normal typing.
- Run tests, frontend lint and frontend build after relevant changes.
- Report changed files, tests performed and manual checks required.
- Do not add dependencies without explaining why they are necessary.
